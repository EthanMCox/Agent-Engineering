## Chat with access to real-world resources, including human-in-the-loop
I experimented with running a chatbot inside a container and allowing it to have access to resources in Docker. One of the things I noticed immediately was that there were some times where I didn't need to worry about giving the bot approval and where it would have been nice if it just worked on its own for a little while and only asked for my permission for truly critical tasks, similar to what something like Github Copilot would do. I think this illustrates the importance of considering the tradeoffs between security and functionality. It's sometimes important to have human approval, but agents can also become more useful if they have a little bit more flexibility in their usage of tools. It was cool to actually put into practice letting the chatbots have more agentic capabilities on the file system.
